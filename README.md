# localnet

Это учебный проект, реализующий клиент-серверное приложение для безопасной передачи файлов по сети (TCP). Утилита позволяет удалённо выполнять базовые команды на сервере (`ls`, `cd`, `getfile`, `sendfile`) и обмениваться файлами с шифрованием содержимого.

**Важно:** Проект предназначен для работы в доверенной локальной сети и служит целям обучения. В текущей версии **команды передаются в открытом виде**, а шифрование применяется только к файлам. Планируется доработка для полного шифрования всех данных.

---

## Архитектура и принцип работы

### Роли

- **Сервер (`main.py`)** – принимает команды от клиента, выполняет их и возвращает результат. Может как принимать файлы от клиента (`getfile`), так и отправлять их клиенту (`sendfile`).
- **Клиент (`client.py`)** – подключается к серверу, принимает команды из ввода оператора на серверной стороне (по сути, сервер инициирует действия, а клиент их исполняет).

### Поток выполнения

1. **Запуск сервера** – указывается порт (по умолчанию `8080`). Сервер генерирует **сеансовый AES-ключ** (128 бит) и отправляет его клиенту при подключении. *Это упрощённый метод; в будущем планируется обмен ключами через RSA.*
2. **Подключение клиента** – клиент получает ключ и сохраняет его для всех последующих шифрований/расшифровок.
3. **Интерактивная сессия** – оператор на сервере вводит команды. Они отправляются клиенту как текст (без шифрования). Клиент интерпретирует команду и возвращает результат:
   - `ls` – список файлов в текущей директории клиента.
   - `cd` – текущая рабочая директория клиента.
   - `getfile <filename>` – клиент **отправляет** файл на сервер (зашифрованно).
   - `sendfile <filename>` – сервер **отправляет** файл клиенту (зашифрованно).
   - `exit` – завершение сессии.
4. **Передача файлов** – файл читается в бинарном режиме, шифруется с помощью **AES-GCM** (с автоматически генерируемым `nonce` и `tag`), затем по сети передаются три компонента:
   - `nonce` (16 байт)
   - `tag` (16 байт)
   - зашифрованные данные (`ciphertext`)
   Каждый компонент отправляется с префиксом длины (4 байта, big‑endian), что гарантирует целостность сообщений.
5. **Приём файлов** – сервер (или клиент) принимает три компонента, расшифровывает их с использованием общего ключа и сохраняет файл в текущей директории.

### Протокол передачи данных

- Все сообщения (команды, ответы, части зашифрованных файлов) передаются по TCP.
- Для каждого блока данных используется простой протокол: **4 байта длины** (в сетевом порядке) + сами данные.
- Файлы шифруются по следующей схеме:
  - Генерируется уникальный `nonce` для каждого файла.
  - Данные шифруются алгоритмом AES-128-GCM.
  - Получаются `ciphertext` и `tag` (16 байт).
  - По очереди отправляются `nonce`, `tag` и `ciphertext` (каждый со своей длиной).

### Используемые криптографические алгоритмы

- **AES-128-GCM** – симметричное шифрование с аутентификацией (обеспечивает конфиденциальность и целостность). Ключ генерируется случайно на сервере при старте сессии.
- В будущем планируется заменить передачу ключа в открытом виде на гибридную схему (RSA + AES).
